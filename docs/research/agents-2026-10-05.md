# Coding-agent integration matrix for Fabric Switchboard

Research date: 2026-10-05. Method: official documentation and source repositories, read on that
date; GitHub links are pinned to the HEAD commit read that day. Nothing was installed or run, and
no request was sent through Switchboard. Every claim carries the URL it came from. A field that
could not be confirmed in a primary source says **unverified**. "Works" below means the config
surface exists; it does not mean an end-to-end request has succeeded.

## What Switchboard offers an agent

| Surface | Address | Source |
|---|---|---|
| MCP server (stdio) | command `switchboard`, args `["mcp"]` | [crates/switchboard-cli/src/mcp.rs](../../crates/switchboard-cli/src/mcp.rs) |
| Anthropic Messages | `http://127.0.0.1:<port>/claude/<pool>` + `/v1/messages` (also `/v1/messages/count_tokens`; the only query string allowed is `?beta=true`) | [proxy lib.rs#L350-L361 @ba2c0ac](../../crates/switchboard-proxy/src/lib.rs#L350-L361) |
| OpenAI Responses | `http://127.0.0.1:<port>/codex/<pool>/v1` + `/responses` | same lines |
| Token | `Authorization: Bearer <token>` or `x-api-key: <token>` | [lib.rs#L327-L348 @ba2c0ac](../../crates/switchboard-proxy/src/lib.rs#L327-L348) |

**State of the code on 2026-10-05.** Released `main` (`0cae07b`, v0.6.x) has no Chat Completions route.
The unreleased WIP commit `ba2c0ac` adds three things. It sits on local branch `agent/agents-support` and was
not pushed when this was written, so the line links above and below are repo-relative and point at that commit's content. First, a
separate *agent token* for third-party agents. Second, `/codex/<pool>/v1/chat/completions`, served only
when the pool's selected account is an OpenAI **API-key** account. Third, a guard that answers 403 when
an agent token reaches a **subscription** account ([lib.rs#L102](../../crates/switchboard-proxy/src/lib.rs#L102),
[#L383-L391](../../crates/switchboard-proxy/src/lib.rs#L383-L391)).
The matrix below rates agents against the released surface (Anthropic Messages and Responses). It
notes separately where the WIP Chat Completions route would help.

**Base-URL shape matters.** Clients disagree about what they append to a base URL. In the table and
sections, "base" is the exact value to configure:

| Client family | Appends | Base to set |
|---|---|---|
| Anthropic SDK / Claude Code / Goose / Zed / litellm / Factory | `/v1/messages` | `http://127.0.0.1:<port>/claude/<pool>` |
| Vercel AI SDK `@ai-sdk/anthropic` (Kilo, Cline, OpenCode), Continue | `/messages` | `http://127.0.0.1:<port>/claude/<pool>/v1` |
| Responses clients (Codex, AI SDK `@ai-sdk/openai`, Zed, Qwen) | `/responses` | `http://127.0.0.1:<port>/codex/<pool>/v1` |

For the AI SDK: its default base is `https://api.anthropic.com/v1` and it appends only `/messages`
([vercel/ai anthropic-provider.ts#L127-L160](https://github.com/vercel/ai/blob/0ca1ab97408d52e7973893cd7f368294b04d9a91/packages/anthropic/src/anthropic-provider.ts#L127-L160)).

## Agents

### 1. Hermes Agent (Nous Research)

- **Kind:** CLI/TUI agent with terminal tools ([repo](https://github.com/NousResearch/hermes-agent)). MIT ([LICENSE](https://github.com/NousResearch/hermes-agent/blob/7157422022ff06f3e632d1dd394ee1253b17ad37/LICENSE)).
- **Install (macOS):** `curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash` ([installation.md#L45](https://github.com/NousResearch/hermes-agent/blob/7157422022ff06f3e632d1dd394ee1253b17ad37/website/docs/getting-started/installation.md#L45)).
- **Binary / headless:** `hermes`. Use `hermes -z "<prompt>"` (final reply only) or `hermes chat --oneshot -q "<prompt>"` ([cli-commands.md#L125-L127](https://github.com/NousResearch/hermes-agent/blob/7157422022ff06f3e632d1dd394ee1253b17ad37/website/docs/reference/cli-commands.md#L125-L127)).
- **MCP:** stdio, in `~/.hermes/config.yaml` under `mcp_servers.<name>`. The CLI form is `hermes mcp add <name> --command CMD --args ...`, with `--args` last ([mcp.md#L33-L39](https://github.com/NousResearch/hermes-agent/blob/7157422022ff06f3e632d1dd394ee1253b17ad37/website/docs/user-guide/features/mcp.md#L33-L39), [cli-commands.md#L1624](https://github.com/NousResearch/hermes-agent/blob/7157422022ff06f3e632d1dd394ee1253b17ad37/website/docs/reference/cli-commands.md#L1624)).

  ```yaml
  mcp_servers:
    switchboard:
      command: "switchboard"
      args: ["mcp"]
  ```
- **Anthropic base URL:** configure a named provider with `providers.<name>.api` (aliases `base_url`/`url`), `key_env` / `api_key` / `key_cmd`, and `transport: anthropic_messages` ([providers.md#L1338-L1354](https://github.com/NousResearch/hermes-agent/blob/7157422022ff06f3e632d1dd394ee1253b17ad37/website/docs/integrations/providers.md#L1338-L1354)).
  - Path: a trailing `/v1` is stripped and the SDK appends `/v1/messages`, so the base is `…/claude/<pool>` ([anthropic_adapter.py#L374-L386](https://github.com/NousResearch/hermes-agent/blob/7157422022ff06f3e632d1dd394ee1253b17ad37/agent/anthropic_adapter.py#L374-L386)).
  - Header: `x-api-key`. Keys shaped like `sk-ant-oat*` switch to Bearer with Claude Code identity headers ([#L455-L469](https://github.com/NousResearch/hermes-agent/blob/7157422022ff06f3e632d1dd394ee1253b17ad37/agent/anthropic_adapter.py#L455-L469)).
  - An `ANTHROPIC_BASE_URL` env var: unverified.
- **OpenAI:** `transport: chat_completions` or `transport: codex_responses`; the docs name "a local Codex proxy" as a use for the latter ([providers.md#L1398](https://github.com/NousResearch/hermes-agent/blob/7157422022ff06f3e632d1dd394ee1253b17ad37/website/docs/integrations/providers.md#L1398)). Which path is appended for Responses: unverified.
- **Notes:** by default Hermes *adopts external logins*, meaning it reads Claude Code's own credential files. Set `auth.adopt_external_logins: false` ([providers.md#L160-L197](https://github.com/NousResearch/hermes-agent/blob/7157422022ff06f3e632d1dd394ee1253b17ad37/website/docs/integrations/providers.md#L160-L197)). See Terms: this would put subscription OAuth into a third-party client.

### 3. Claude Code

- **Kind:** CLI, plus VS Code/JetBrains extensions and a desktop app ([setup](https://code.claude.com/docs/en/setup)). Proprietary: "All rights reserved" ([LICENSE.md](https://github.com/anthropics/claude-code/blob/2bfb629dfaff0c8318047a4beb93cf1dc5b58b18/LICENSE.md)).

- **MCP:** user/local scope lives in `~/.claude.json`, project scope in `.mcp.json` ([mcp](https://code.claude.com/docs/en/mcp)).

  ```bash

  ```
- **Anthropic base URL:** `ANTHROPIC_BASE_URL=http://127.0.0.1:<port>/claude/<pool>` (no `/v1`).
  - `ANTHROPIC_API_KEY` is sent as `X-Api-Key`; `ANTHROPIC_AUTH_TOKEN` is sent as `Authorization: Bearer` ([env-vars](https://code.claude.com/docs/en/env-vars)).

- **OpenAI:** none. The only formats are Anthropic Messages, Bedrock and Vertex ([llm-gateway-protocol](https://code.claude.com/docs/en/llm-gateway-protocol)).
- **Notes:** this is Switchboard's primary, already-integrated client. With only `ANTHROPIC_BASE_URL` set, the claude.ai login stays active ([llm-gateway](https://code.claude.com/docs/en/llm-gateway)).

## Terms: which credentials may go to which client

### Anthropic (Claude subscription OAuth)

Claude Code's **Legal and compliance** page, read 2026-10-05 ([code.claude.com/docs/en/legal-and-compliance](https://code.claude.com/docs/en/legal-and-compliance)), section "Authentication and credential use":

> **OAuth authentication** is intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications.

> Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or session tokens — sign-in to a Claude account must complete through Anthropic's own flow.

> Nor does it prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription […] Anthropic reserves the right to take measures to enforce these restrictions and may do so without prior notice.

The same page puts Free/Pro/Max users under the Consumer Terms. The **Consumer Terms** (effective 2025-10-08, [anthropic.com/legal/consumer-terms](https://www.anthropic.com/legal/consumer-terms)) add two relevant clauses:

- §2: "You may not share your Account login information, Anthropic API key, or Account credentials with anyone else or make your Account available to anyone else."
- §3(7): users may not "access the Services through automated or non-human means, whether through a bot, script, or otherwise", except via an API key or with explicit permission.

What this means for Switchboard:

- A Claude **subscription** account may be routed **only to the unmodified Claude Code binary**. Every other agent in this matrix needs an **Anthropic API-key** account. The WIP guard at [lib.rs#L102](../../crates/switchboard-proxy/src/lib.rs#L102) enforces exactly this split.
- Several agents carry code that impersonates Claude Code when handed an `sk-ant-oat…` token:
  - Hermes ([anthropic_adapter.py#L455-L469](https://github.com/NousResearch/hermes-agent/blob/7157422022ff06f3e632d1dd394ee1253b17ad37/agent/anthropic_adapter.py#L455-L469))
  - pi ([anthropic-messages.ts#L1013-L1018](https://github.com/earendil-works/pi/blob/b78e6a9085343ec0f308c3d377da72528b4cf7ee/packages/ai/src/api/anthropic-messages.ts#L1013-L1018))
  - omp ([models.md#L148](https://github.com/can1357/oh-my-pi/blob/1c0993c3d12e70042169a951663bb2702e2c0a9e/docs/models.md#L148))
  - OpenClaw ([anthropic-transport-stream.ts#L79-L87](https://github.com/openclaw/openclaw/blob/78e406060b56bac2d09810161ac7b483861e9879/packages/ai/src/transports/anthropic-transport-stream.ts#L79-L87))

  Hermes also adopts Claude Code's credential files by default. Switchboard must never hand these agents a subscription token, and setup instructions should tell users to turn off Hermes' `auth.adopt_external_logins`.
- **Open question for the operator (not settled here):** the sentence "developers may not collect, store, or intermediate Claude.ai credentials or session tokens" reads on Switchboard's own design, which stores Claude OAuth credentials and relays managed Claude Code sessions through its proxy. Whether a local, single-user account manager driving the unmodified Claude Code falls under that sentence is a legal reading this research does not make. It needs a decision, or a question to Anthropic ([contact sales](https://www.anthropic.com/contact-sales), as the page itself suggests).

### OpenAI (ChatGPT subscription sign-in for Codex)

- **Terms of Use**, effective 2026-01-01. Read through the Internet Archive capture of 2026-10-04, because openai.com returned 403 to automated fetches: [web.archive.org/…/openai.com/policies/row-terms-of-use/](https://web.archive.org/web/20261004073440/https://openai.com/policies/row-terms-of-use/).
  - Registration: "You may not share your account credentials or make your account available to anyone else and are responsible for all activities that occur under your account."
  - What you cannot do: "Automatically or programmatically extract data or Output", and "circumvent any rate limits or restrictions or bypass any protective measures".
- **Codex authentication docs** ([learn.chatgpt.com/docs/auth](https://learn.chatgpt.com/docs/auth)):
  - "Treat `~/.codex/auth.json` like a password: it contains access tokens."
  - "API keys are still the recommended default for automation."
- The CI page adds: "Use one `auth.json` per runner or per serialized workflow stream. Do not share the same file across concurrent jobs or multiple machines" ([ci-cd-auth](https://learn.chatgpt.com/docs/auth/ci-cd-auth)).
- **Sign in with ChatGPT for third-party apps** ([cookbook](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt)) is the sanctioned route for ChatGPT plan usage outside OpenAI's own clients:
  - "ChatGPT plan usage is available to open-source projects, personal projects that run locally, and selected private apps."
  - Each app gets its own registration through OpenAI's SDK (`@siwc/local`), and "Separate registrations stay separate".
  - "If you're building a paid or remotely hosted app, join the waitlist."
  - Requests go to the public Responses API with that app's own OAuth token.
- Press coverage of DevDay 2026-09-29 names OpenCode, Amp, Warp, OpenClaw and Devin among the launch partners. That is a secondary source, and no official partner list was read (**unverified**), e.g. [The New Stack](https://thenewstack.io/sign-in-with-chatgpt/).

What this means for Switchboard: a ChatGPT-subscription account captured for Codex should be routed **only to Codex** (CLI, IDE or desktop). A third-party agent that wants plan usage must use its own "Sign in with ChatGPT" registration, not a token relayed from Codex's `auth.json`. Every other agent on the `/codex/<pool>/v1` route needs an **OpenAI API-key** account. This matches the WIP subscription guard and the API-key-only Chat Completions route.

### Matrix consequence

With subscription accounts excluded, a third-party agent is useful through the proxy only when its pool holds an API-key account. MCP (`switchboard mcp`) carries no model credential and is unaffected by either provider's terms.
