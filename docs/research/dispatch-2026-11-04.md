# SB-247: `switchboard dispatch`, a session started for a board request

**State:** design, 2026-11-04. Row: [SB-247](../evidence/backlog.md). Source: the operator's decision of 2026-11-04
(about 09:45 UTC, Fabric session `5d9bed98`, relayed verbatim by fabric-32; quoted in the row) and Fabric's spec
[on-demand sessions](https://github.com/passioncode-ai/fabric/blob/39b68cca01112b590b499fd5659953de33960dab/docs/evidence/specs/2026-11-04-on-demand-sessions.md)
§3.5, §4, §5 (commit `39b68cca`). Fabric owns the dispatcher, the packet and the switch; Switchboard owns the start.

## What Switchboard does

`switchboard dispatch --dir <folder> --workflow <wf> --handoff <handoff-id> --reason request --permissions ask|all
--timeout-minutes <n> [--json]` starts the machine's default agent on the request's workflow, with no person:

1. The folder's group, the account and its ceilings come from `continue`'s path (`continue_default`,
   `continue_checks`, the spend gate for a paid agent): nothing new decides who runs.
2. The run is non-interactive: Claude Code as `claude -p` with the packet as the prompt and the exit contract as
   `--append-system-prompt`, Codex as `codex exec`, each in the account's isolated home, with
   `FABRIC_DISPATCH_WORKFLOW=<wf>` and `SWITCHBOARD_LAUNCH_ID` in its environment. No Terminal on macOS, no PowerShell
   on Windows: Switchboard's own process starts it. With *Open hand-overs in Fabric* on, Fabric's console shows it.
3. One live run per workflow: a second `dispatch` for the same workflow while the first runs answers the same
   `launch_id` with `state: running`.
4. The run is stopped by `switchboard dispatch stop --launch-id <id>` (Fabric's command) or by the time limit:
   the process group on macOS and Linux, `taskkill /T` on Windows. The launch record gets `ended: stopped` or
   `ended: timed_out`.
5. The launch record says `launched_by: fabric` with the workflow; Fabric reads the end through
   `switchboard sessions --launch-id <id>` (SB-212, unchanged).

Answer: `{launch_id, agent, account_id, state: started | running | refused, reason?}`. Refusals, before anything starts:
`no_agent` (no default agent with room; Fabric's `deferred-no-agent`), `not_in_group`, `ceiling_reached`,
`spend_unknown`, `agent_not_installed`, `permission_mode`, `handoff_refused`.

## Decisions

- **D-1. Fabric opens the hand-over.** The workflow is Fabric's (owner `service:fabric`), and Observatory gives keys
  only to the holder of its lease (spec §3.4). `continue` offers with reason `limit`, which Observatory admits only
  after the executor has been silent two minutes, so Switchboard cannot offer a fresh workflow. Fabric, which holds
  the lease, creates the offer to the default agent's provider (`observatory_handoff_create`, reason `plan_route`,
  `to.provider` from `switchboard agents`, no account) and passes its id; the started session accepts it, narrowed to
  the account Switchboard chose. The lease never travels through Switchboard. **Agreed** by Fabric 2026-11-04
  (session `5d9bed98`, fabric-32), with the full form, the stop command and the refusal codes; Fabric records it in its
  spec §3.5.
- **D-2. The permission mode comes from Fabric.** `--permissions all` runs Claude Code with
  `--dangerously-skip-permissions` and Codex with `--dangerously-bypass-approvals-and-sandbox` (checked in `codex exec --help` 2026-11-04); `ask` runs them with their defaults. Switchboard does not
  read Fabric's `agentPermissions` file. The operator's words («дефолтная агентка со всеми permission'ами… включенными
  по дефолту») are Fabric's setting to carry; money, deletion and publication still go through
  `fabric_effect_request` (spec §6).
- **D-3. Only agents that run headless take a dispatch.** Claude Code and Codex in wave 1. An agent that asks less than
  the mode allows is refused `permission_mode` (SB-82 D-6, the operator's decision of 2026-11-02).
- **D-4. The time limit is Fabric's number.** `--timeout-minutes`, default 60; Fabric passes less when the request's
  deadline is earlier. The owner's background pass stops a run past it, so a quit app stops nothing it did not start:
  a dispatched run outlives the app like a Terminal session, and its limit is enforced again at the next start.
- **D-5. Analytics: counts only.** `dispatch` {state, reason, agent_kind, platform} and `dispatch_ended`
  {outcome, duration bucket}, through docs/ANALYTICS.md's rule; the request's text, folder and workflow id never.
