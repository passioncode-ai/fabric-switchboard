# Работа вашей организации в Switchboard

[English version](ORGANIZATION.md)

Это руководство для сотрудника организации: для нового сотрудника или для того, кто добавляет
работу компании на свой компьютер. В конце у группы организации будет ваше место, в которое
выполнен вход, терминалы в её папках будут работать в её контексте, а одна сессия это подтвердит.
Ваши личные аккаунты и история остаются отдельно от рабочих.

Согласие в браузере и вход в аккаунт вы выполняете сами. Всё остальное можно сделать в окне
приложения, в терминале или поручить своему агенту для программирования (попросите его выполнить
`switchboard onboard` и следовать подсказкам).

Окно, агент и это руководство опираются на один и тот же список шагов. На любом шаге эта команда
покажет, где вы находитесь:

```sh
switchboard --json onboard --status
```

Каждый шаг в ответе отмечен как `done` (готово), `todo` (сделать), `needs_person` (нужны вы) или
`optional` (по желанию). Когда настройка завершена, `data.complete` равно `true`.

**Что нужно заранее**

- Приглашение в команду вашей организации у провайдера (Claude Team или рабочее пространство
  ChatGPT), отправленное на ваш адрес в организации. Оно придёт в вашу личную почту, если
  организация пересылает этот адрес вам.
- Установленный Claude Code или Codex. Подписка в Switchboard не входит.
- Для шага 3: файл настроек от администратора организации или папки, где лежит код организации.

## 1. Установите Switchboard

Скачайте приложение для своей системы на [странице загрузки](https://passioncode.ai/switchboard/#download)
и установите его, как описано в [INSTALL.md](INSTALL.md), или установите его вместе с другими
инструментами PassionCode.ai одной командой:

```sh
npx --yes @passioncode-ai/passioncode@latest setup --yes --json
```

Откройте приложение один раз. Оно спросит, можно ли отправлять анонимную статистику
использования (ответ можно изменить позже в разделе «О программе»), и покажет короткий обзор.
После этого приложение запускается при входе в систему и продолжает работать, когда вы закрываете
его окно.

Сделайте команду `switchboard` доступной в `PATH`, чтобы ею могли пользоваться вы и ваш агент:
в macOS «Агенты» → «Создать ссылку switchboard в ~/.local/bin»; в Linux пакет .deb кладёт её в
`/usr/bin`; в Windows `switchboard.exe` устанавливается рядом с приложением, а его путь показан
на странице «Агенты».

**Проверка:** `switchboard --version` выводит версию, а `switchboard --json onboard --status`
отвечает списком шагов.

## 2. Подключите PassionCode.ai

Если ваша организация работает в PassionCode.ai, подключите его: «Организации» →
«Подключить PassionCode.ai…» или в терминале:

```sh
switchboard org connect
```

Браузер откроет страницу согласия PassionCode.ai; подтверждаете его вы. Затем ваши организации
появятся в Switchboard с названиями и доменами, и Switchboard будет перечитывать их каждые 6 часов.

Если организация не пользуется PassionCode.ai, добавьте её вручную: «Организации» →
«+ Новая организация» или `switchboard org add "Acme" --domain acme.example`.

**Проверка:** `switchboard --json org passioncode` отвечает `"connected": true` и `"state": "ok"`;
`switchboard org list` называет вашу организацию; в `onboard --status` шаг `organization`
отмечен как `done`.

## 3. Группа организации

Группа объединяет папки проектов и собственные аккаунты. Сессии в её папках используют только её
аккаунты. Организации нужна одна группа на этом компьютере.

Когда организация появилась, окно показывает карточку «Настройка {organization} на этом
компьютере» над страницей «Аккаунты» и вверху страницы «Организации». В ней те же пять шагов, что
и в этом руководстве, и одно действие за раз.

- **Если администратор дал файл настроек.** В нём группа и её репозитории, но никогда не
  аккаунты. Сначала посмотрите, что изменится, затем примените:

  ```sh
  switchboard settings import <файл настроек> --under <папка с вашим кодом>
  switchboard settings import <файл настроек> --under <папка с вашим кодом> --apply
  ```

  `--under` указывает папку с вашими копиями репозиториев; там Switchboard найдёт репозитории
  группы.
- **Если файла нет.** На карточке «+ Группа для {organization}» открывает окно группы с уже
  выбранной организацией. Или создайте группу и привяжите её в терминале:

  ```sh
  switchboard project save --name "Acme" --folder <абсолютный путь к репозиторию>
  switchboard project edit --pool <идентификатор группы> --organization <идентификатор или название организации>
  ```

  `switchboard project list` показывает идентификатор группы, `switchboard org list`
  идентификатор организации.

**Проверка:** в `onboard --status` шаг `org_group` отмечен как `done` и называет группу.

## 4. Ваше место

Примите приглашение провайдера из почты. Затем войдите в это место в группе: на карточке
«Войти с адресом {organization}» или в терминале:

```sh
switchboard login begin --provider claude --pool <идентификатор группы>
switchboard login status <идентификатор входа>
switchboard login finish <идентификатор входа>
```

Официальный вход провайдера откроется в окне терминала; входите вы сами. Для места в Codex укажите
`--provider codex` (в окне: «+ Добавить аккаунт» → «Войти в другой аккаунт Codex»). Аккаунт
получает значок вашей организации, например по домену своего адреса.

Если вы сначала вошли в другом месте, уведомление предложит «Перенести в «{group}»». Без вас
Switchboard аккаунты не переносит.

**Проверка:** в `onboard --status` шаг `seat` отмечен как `done`.

## 5. Терминалы в папках организации

Когда группа принадлежит организации, установленное приложение добавляет один помеченный блок в
файл запуска каждой оболочки на компьютере. Тогда `claude` и `codex`, запущенные из терминала в
папках группы, работают в контексте организации: со своей домашней папкой для Claude Code и
Codex (история, настройки, вход) и с `SWITCHBOARD_CONTEXT=org:<id>`. Когда вы выходите из папки,
возвращаются ваши собственные настройки. Приложение сообщит об этом один раз уведомлением. Это
включено по умолчанию, делать ничего не нужно.

Новые терминалы подхватывают привязку сразу; уже открытый терминал её не подхватит, откройте новый.

```sh
switchboard shell status     # включена ли привязка, есть ли она в этом терминале, группа этой папки
switchboard shell off        # убрать блок из всех файлов запуска и больше не добавлять
switchboard shell on         # вернуть его
```

`shell off` возвращает каждый файл запуска байт в байт. В окне есть тот же переключатель:
«Группы» → «Терминалы в папках организаций» → «Выключить» или «Включить».

Полезно знать:

- Claude Code получает домашнюю папку организации в самой папке группы, где лежит файл маршрута
  Switchboard; во вложенной папке `claude` работает с вашими собственными настройками. Codex
  следует за группой и во вложенных папках.
- Если у группы нет аккаунта Codex, `codex` в её папках остаётся на вашем собственном входе;
  `shell status` так и пишет.
- Файл запуска, который является ссылкой (например, от менеджера dotfiles), принадлежит другому
  пользователю или не является текстом, остаётся нетронутым; `shell status` покажет строку, которую
  нужно добавить самостоятельно (`switchboard shell init <оболочка>`).
- Скрипты и редакторы, которые запускают Claude Code без интерактивной оболочки, привязку не
  загружают; аккаунт у них всё равно определяется папкой группы.

**Проверка:** `switchboard shell status` сообщает, что привязка включена, а в новом терминале
выводит «This terminal: the hook is loaded.» (команда отвечает по-английски); в папке группы
`echo $SWITCHBOARD_CONTEXT` выводит `org:<id>`. В `onboard --status` шаг `hook` отмечен как
`optional` с `"terminals": "active"`.

## 6. Запустите работу

Работайте как обычно в папках группы. Чтобы подтвердить настройку, запустите одну сессию из
Switchboard (обычный `claude` в терминале не считается сессией, запущенной Switchboard, и не
записывается):

```sh
switchboard launch --provider claude --mode managed --working-directory <папка группы>
```

Или нажмите «Запустить…» на карточке аккаунта в окне.

**Проверка:** `switchboard sessions` показывает сессию с названием вашей организации, а
«Журнал» → «Сессии» показывает её значок. В `onboard --status` шаг `launch` отмечен как `done`,
а `data.complete` равно `true`.

## 7. Уход из организации

- **Ваше место убрали.** Когда провайдер окончательно отклоняет вход в это место, на его карточке
  появляется: «Вход в аккаунт {label} больше не действует. Если ваше место в {organization} убрали,
  обратитесь к администратору организации; чтобы продолжить работу с аккаунтом, войдите снова.»
  Switchboard перестаёт его выбирать. Если закончились все места группы, карточка группы сообщает,
  что сессии в её папках получают отказ, пока вы не войдёте хотя бы в один аккаунт.
  **Проверка:** в `onboard --status` шаг `seat` отмечен как `needs_person` и считает места,
  вход в которые закончился.
- **Вы вышли из организации в PassionCode.ai.** После следующего чтения карточка организации
  сообщает, с какой даты её нет среди ваших организаций в PassionCode.ai. **Проверка:**
  `switchboard --json org passioncode` показывает её в `released` с датой.
- **Что остаётся на компьютере.** При уходе Switchboard ничего не удаляет: организация, её группа
  (которая по-прежнему не принимает ваши другие аккаунты), аккаунт, его статистика и домашние
  папки организации с историей остаются, пока вы их не удалите.
- **Как удалить.** «Организации» → «Удалить…» на её карточке (или `switchboard org remove
  <идентификатор организации>`): её группы становятся личными. `switchboard shell off` убирает
  блок из файлов запуска. `switchboard uninstall` показывает, что будет удалено с компьютера;
  добавьте `--yes`, чтобы удалить.

## Windows, macOS и Linux

На компьютере сотрудника с Windows это ещё не проверялось: шаги для Windows реализованы и пока
проходят только ночные тесты на тестовых машинах Windows.

| Шаг | macOS и Linux | Windows |
|---|---|---|
| 1. Установка | macOS: приложение в «Программах», ссылка на `switchboard` в `~/.local/bin`. Linux: пакет .deb, `switchboard` в `/usr/bin` | установщик для вашей учётной записи; `switchboard.exe` рядом с приложением (путь показан на странице «Агенты») |
| 2. Подключение | страница согласия открывается в браузере по умолчанию | так же |
| 3. Группа | `--under` указывает папку с кодом, например `~/code` | `--under` указывает папку с кодом, например `C:\Users\you\code` |
| 4. Место | вход хранится в Связке ключей (macOS) или в Secret Service (Linux) | вход хранится в диспетчере учётных данных Windows |
| 5. Терминалы | zsh `.zshrc`, файл входа bash в macOS или `.bashrc` в Linux, собственный файл fish в `~/.config/fish/conf.d` | профиль `Microsoft.PowerShell_profile.ps1` для Windows PowerShell 5.1 и для PowerShell 7 в папке «Документы» (и когда её перенёс OneDrive). Если политика выполнения `Restricted` или `AllSigned`, профили не загружаются: Switchboard не трогает профиль, никогда не меняет политику, а `shell status` пишет `policy_blocked`. Если PowerShell работает в режиме ограниченного языка (Constrained Language Mode), пишет `constrained_language`. Командная строка и Git Bash не поддерживаются. В папке группы `$env:SWITCHBOARD_CONTEXT` выводит `org:<id>` |
| 6. Запуск | сессия открывается в Терминале (macOS) или в вашем приложении терминала (Linux) | сессия открывается в новом окне PowerShell |
| 7. Уход | так же | так же |

Что стоит за каждым шагом: список шагов собирает `onboarding::steps` в
[crates/switchboard-runtime/src/onboarding.rs](../crates/switchboard-runtime/src/onboarding.rs);
команды описаны в [CLI](CLI.md), контракты в [CONTRACTS](CONTRACTS.md), сценарии с SCN-074
по SCN-079 в [scenarios](ux/scenarios.md).
