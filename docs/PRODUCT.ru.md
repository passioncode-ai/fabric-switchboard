# Fabric Switchboard: решение и границы первой версии

Это новый самостоятельный проект в Fabric org (`passioncode-ai`). Под «Cloud Swap» в исходном запросе принят связанный `realiti4/claude-swap`. Пользователь дал три ссылки и попросил исследовать четыре репозитория; четвёртым выбран `farion1231/cc-switch`. Это явно сделанное допущение, а не утверждение, что пользователь прислал четвёртую ссылку.

[Research](research/README.md) содержит разбор зафиксированных исходников четырёх проектов. [SPEC](SPEC.md) — полный технический контракт. [Evidence](evidence/verification.md) отвечает, какие части уже исполнены и проверены. Ниже — продуктовые решения по всем основным осям.

## Что берём из исследованных подходов

| Источник | Полезный принцип | Принятое решение |
|---|---|---|
| codex-account-switcher | явные стадии сохранения/подмены/проверки, нативная интеграция | отделить выбранную конфигурацию от доказанного ответа; существующий Desktop не перехватывать незаметно |
| subswapper | изолированные home и локальный прокси с подстановкой auth на запросе | два отдельных режима запуска, immutable identity каждого уже начатого запроса |
| claude-swap | терминальная эргономика, Keychain, профили и locks | официальный вход в отдельный home, один владелец refresh lineage, настоящий Keychain без Base64 fallback |
| cc-switch | настольный workbench, Tauri/Rust, богатые состояния аккаунтов | общий Rust backend и тонкий TypeScript UI; секреты вынесены из JSON/SQLite в OS vault |

Это архитектурный синтез, не включение чужого кода в продукт. Детальные подтверждения, включая недостатки каждого решения, находятся в research; популярность и лицензия не считаются доказательством безопасности.

## Оси продукта

| Ось | Решение в 0.1 | Следующая ступень |
|---|---|---|
| ОС | macOS 14+, локальная Apple Silicon сборка | отдельная Windows native acceptance, затем Intel Mac |
| Клиент | Claude Code и Codex CLI через новый запуск | явный idle/restart handoff для Codex Desktop |
| Авторизация | API key, Claude setup token, OAuth snapshot | refresh owner с блокировками и восстановлением lineage |
| Добавление | официальный login либо ручной импорт | resumable onboarding после падения |
| Хранилище | Keychain для canonical credentials, private metadata | Windows vault, зашифрованный перенос между машинами |
| Контекст | provider + pool, выбранный каталог проекта | сохранённые привязки проектов к пулам |
| Переключение | isolated: новый запуск; managed: следующий HTTP-запрос | supervised drain/restart; WebSocket только отдельным проверенным адаптером |
| Политика | явный выбор человеком | рекомендации, затем отдельно включаемая автоматическая ротация |
| Лимиты | timestamp и максимум сообщённых окон | все окна, reset time, cooldown/hysteresis |
| История | отдельные native home; bounded metadata journal | supervisor и диагностический экспорт без секретов |
| Дистрибуция | локальная `.app` | Developer ID, notarization, подписанный updater |

## Аккаунты: от добавления до удаления

**Добавить.** Пользователь выбирает провайдера, способ входа, понятную подпись и пул. Подпись не используется как идентичность и не становится частью shell-команды. Backend проверяет формат независимо от браузерной формы. Успешный parse означает только поддерживаемый формат, а не действительность подписки.

**Официальный вход.** Создаётся приватный `logins/UUID`; только новый CLI получает CODEX_HOME или CLAUDE_CONFIG_DIR. Вход выполняется официальным клиентом. Finish доступен после успешного завершения процесса, затем захватывается именно credential этого профиля. Глобальный logout не вызывается. Cancel не убивает Terminal: просит закрыть/завершить login и очищает только staging. После краша автоматического восстановления login пока нет; безопасное ручное восстановление описано в [operations](OPERATIONS.md).

**Хранить.** Один UUID связывает метаданные с Keychain item. Credential не возвращается через IPC, не попадает в activity, ошибки или frontend snapshot. Публикация метаданных атомарная; ошибка сохранения после добавления секрета запускает удаление только нового item. Ошибка очистки не скрывается как успех. Metadata corruption запрещает запуск, вместо появления ложного пустого списка.

**Выбрать.** Выбор относится к точному provider/pool. Личный Claude не становится резервом рабочего Codex. Нельзя выбрать disabled/expired/missing credential. Сохранённый route отображается как Selected for next request; это не Connected/Verified.

**Изменить.** В первой версии можно поменять подпись или отключить аккаунт. Отключение убирает его route. Перенос между пулами и редактирование токена на месте не делаются скрыто: используется новый credential profile, чтобы не смешивать историю и lineage.

**Удалить.** Выбранный аккаунт сначала нужно заменить или отключить. Активный isolated home защищён от удаления. Локальная запись и vault item удаляются; это не отзыв ключа у провайдера. Между Keychain и файлом нет общей транзакции: при частичном сбое остаётся видимая непригодная запись с повторяемым удалением. Managed history принадлежит пулу, а не одному аккаунту.

## Два режима сессии

**Isolated.** Пользователь выбирает каталог проекта; процесс открывается там, но authentication home находится отдельно. CLI получает рабочую копию только необходимой авторизации в private file. Выбор другого аккаунта в менеджере на запущенный isolated CLI не влияет. По истечении OAuth нужен новый вход; refresh token в рабочую копию не передаётся.

**Managed.** В home нет provider secret: только loopback URL и случайная capability текущего запуска приложения. Прокси получает snapshot `(account, credential)` при поступлении каждого запроса. Если пользователь выбрал другой аккаунт, пока идёт ответ, первый ответ использует старый snapshot до конца; следующий запрос берёт новый. Приложение должно продолжать работать. После его перезапуска нужно перезапустить managed CLI.

История в pool home остаётся локально общей для его managed launches; перенос истории не означает перенос server-side conversation identity между аккаунтами. Совместимость реального клиента и ответа ещё должна быть измерена по exact version.

## Ошибки и наблюдаемость

Activity содержит ограниченный словарь событий и UUID. Для успешного HTTP-статуса сначала записывается начало потока, и только после EOF — завершение; обрыв не считается успехом. Provider error body возвращается самому CLI, но не хранится в журнале приложения.

401/403/429/5xx, timeout и обрыв не вызывают повтор. Это исключает собственный автоматический replay со стороны Switchboard; внешний CLI может иметь свою retry-политику, которую нужно отдельно наблюдать. Прокси запрещает redirects, произвольные upstream URL, браузерный Origin, чужой Host, upgrade и неизвестные маршруты. Header allowlist исключает перенос caller credentials/cookies. Тело запроса и число одновременных потоков ограничены.

Usage обновляется по кнопке, а для Claude дополнительно из доступных response headers. Неизвестное значение отображается неизвестным. Максимальная загрузка доступного окна не является балансом денег или прогнозом исчерпания. Старое значение сохраняется при ошибке и помечается stale; API billing не выдумывается из subscription quota.

## Стек и границы модулей

Rust хранит секреты, маршруты и состояние; Tokio/axum/reqwest обслуживают ограниченный HTTP/SSE proxy. Tauri 2 предоставляет macOS shell и типизированные команды. TypeScript/Vite рисует три экрана без framework-компонентов; UI не имеет shell/filesystem capability. macOS Security.framework вызывается напрямую. JSON выбран для небольшого ограниченного состояния с атомарной заменой, а не для бесконечного лога.

[CONTRACTS](CONTRACTS.md) фиксирует API модулей и IPC. Стабильная граница Vault позволяет заменить только OS persistence при переносе; Windows требует собственного DACL/reparse-point/atomic-replace слоя и терминального launcher, а не условного `chmod`.

## Критерий готовности и очередь

Первая версия считается инженерно собранной, когда source pins, Rust checks, frontend build, native bundle, синтетический Keychain и проверка request-boundary switching проходят. Приёмка пользователем дополнительно требует реальных logins/requests и проверки окна. Эти уровни записаны раздельно в [evidence](evidence/verification.md).
