# M2: across machines

No P0. The most serious: a recalled seat accepts whatever sign-in the other side hands back; a key change on the other machine reads as "did not answer over ssh"; from the MacBook the operator can still only launch (CLI), attach, end or close a copy on the Studio.

## How this machine reaches another one today

Every call goes over the system `ssh` with the remote command quoted as one string (`fabric-sessions-core/src/cli.rs:5`). Two runners: `ssh_runner` (`account_send.rs:1032`: `BatchMode=yes`, `ConnectTimeout=15`, 120 s, 20 s for reads, no keep-alive, no ControlMaster) and `exec_ssh` (`switchboard-cli/src/main.rs:4751`: replaces the CLI process with `ssh -t|-T -o ConnectTimeout=15 <target> -- ...`, no BatchMode, no machine proof). Above them, the machine proof (`machine_proof.rs`): `--json machines prove --nonce` before an operation, pinning the other machine's key by ssh name in `machine-keys.json`.
